# MontegsModAnalyzer

Приложение для сканирования модов Minecraft и обнаружения читов, обфускации и подозрительных источников загрузки.

---

## Как пользоваться

При запуске скрипт запрашивает путь к папке `mods`:

- Введи полный путь к папке (например, `C:\Users\User\AppData\Roaming\.minecraft\mods`)
- После сканирования окно остаётся открытым — нажми **Enter** для выхода.

---

## Как это работает

### Этап 1: Проверка базы данных

Скрипт вычисляет **SHA-1** каждого JAR файла и проверяет его в базе Modrinth:

**Modrinth API** - `https://api.modrinth.com/v2/version_files`

- Основная и единственная внешняя база проверенных модов
- Проверка идёт **только по SHA-1** (жёсткая привязка к содержимому файла)
- Если SHA-1 найден - мод получает источник `Modrinth (SHA-1)`

**Modrinth (метаданные)** — резервный способ

Если SHA-1 не найден, скрипт ищет реальную ссылку `modrinth.com/mod/<slug>` внутри метаданных мода:

- `fabric.mod.json`
- `quilt.mod.json`
- `META-INF/mods.toml`
- `META-INF/neoforge.mods.toml`
- `META-INF/MANIFEST.MF`
- `pack.mcmeta`

Если ссылка есть - источник помечается как `Modrinth (метаданные)`.

> Поиск по имени файла **не используется** - чтобы избежать ложных срабатываний (например, самодельный `FreeCam.jar` больше не будет отмечен как официальный мод Modrinth).

### Этап 2: Анализ паттернов (для ВСЕХ модов, включая «проверенные»)

Даже если мод найден в Modrinth, он всё равно проверяется на читы и обфускацию. Скрипт:

1. Открывает JAR через `ZipFile`
2. Ищет читерские паттерны **в двух местах**:
   - в сырых байтах всех файлов (`jar.read_bytes()`)
   - в именах entry внутри архива (`.class`, `.json`, пути пакетов)
3. Анализирует `.class` файлы на обфускацию

### Этап 3: Детектор обфускации

Обфускация определяется по двум уровням:

**A) По именам `.class` файлов:**

- CJK символы (китайский / японский / корейский)
- L/I-имена вида `llllLLLlllll`, `IIlIlIlI`
- Кириллица в именах (гомоглифы)
- `$` в начале имени класса
- hex имена длиной 16+ символов
- `class_123` / `func_1234` / `method_5678`
- Пакеты из одной буквы (`a/b/c/Foo`)
- Много коротких имён (1–2 символа) - ≥ 40% классов

**B) По содержимому `.class` (байтам):**

- Ищутся токены `[lLiI]{4,}` внутри байткода
- Ловит обфусцированные методы и поля (`lllI`, `IIIII`, `lll`), даже если сам класс называется нормально (`TextureHelper`)
- Порог: ≥ 8 токенов на класс

## Отслеживание источника загрузки

Скрипт читает `Zone.Identifier` (альтернативный поток данных NTFS в Windows), чтобы определить, откуда был скачан `.jar`.

**Безопасные источники:**

- CurseForge
- Modrinth

**Сомнительные источники:**

- Discord
- MediaFire
- GitHub
- MEGA
- Dropbox
- Google Drive

---

## Обнаруженные чит-паттерны

Скрипт содержит словарь читерских паттернов с краткими описаниями в скобках. Примеры по категориям:

**PvP:**

`AimAssist` (автонаведение на цель), `AutoCrystal` (автоустановка/взрыв кристаллов), `TriggerBot` (автоатака при наведении), `Hitbox` / `Hitboxes` (расширение хитбоксов), `ShieldBreaker` (автоломание щита), `ShieldDisabler` (отключение щита), `KillAura` (автоатака по игрокам), `AntiKnockback` (отмена отбрасывания), `Backtrack` (откат позиций для попаданий), `NoHitDelay` (убрать задержку удара)

**Movement:**

`JumpReset` (сброс прыжка), `NoJumpDelay` (убрать задержку прыжка), `SafeWalk` (не падать с края), `NoSlow` (не замедляться)

**Visuals:**

`FreeCam` / `Freecam` (свободная камера), `PingSpoof` (подмена пинга), `XRay` (просвечивание блоков), `ChestESP` / `PlayerESP` / `MobESP` / `ItemESP` (подсветка объектов сквозь стены)

**Automation:**

`FastPlace` (быстрая установка блоков), `AutoTotem` (авто-тотем в руку), `AutoArmor` (авто-надевание брони), `InventoryTotem` (авто-тотем из инвентаря), `ChestStealer` (авто-кража из сундуков), `AutoEat` (авто-еда), `AutoClicker` (авто-кликер), `FastEXP` (быстрый опыт), `AutoTool` (авто-выбор инструмента), `Scaffold` (авто-мост под ноги)

## Приоритет статусов

Каждый мод получает ровно один статус по приоритету:

```
SUSPECT  >  OBFUSCATED  >  VERIFIED  >  UNKNOWN
```

- **SUSPECT** - найден хотя бы один чит-паттерн (даже если мод есть на Modrinth)
- **OBFUSCATED** - паттернов нет, но код обфусцирован
- **VERIFIED** - мод найден на Modrinth по SHA-1 или по ссылке в метаданных, читов нет
- **UNKNOWN** - ни в базе, ни паттернов, ни обфускации

## Вывод

Скрипт разделяет моды на **четыре** группы:

**ПРОВЕРЕННЫЕ МОДЫ (зелёный)**

- Найдены в Modrinth (по SHA-1 или по ссылке в метаданных)
- Не содержат читерских паттернов
- Не обфусцированы

**НЕИЗВЕСТНЫЕ МОДЫ (бежевый)**

- Отсутствуют в базе
- Паттернов и обфускации нет
- Источник загрузки неизвестен

**ОБФУСЦИРОВАННЫЕ МОДЫ (фиолетовый)**

- Паттернов не найдено
- Но код обфусцирован (L/I-имена, CJK, hex, гомоглифы и т.п.)
- Выводится список причин и пример имени

**ПОДОЗРИТЕЛЬНЫЕ МОДЫ (красный)**

- Содержат один или несколько читерских паттернов
- Для каждого паттерна выводится его краткое описание в скобках
- Если мод при этом есть на Modrinth - указывается источник и ссылка
- Если обфусцирован - дополнительно перечисляются причины обфускации
